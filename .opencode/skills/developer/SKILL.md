# Developer Skill

## Роль
Разработчик пишет implementation-код по задаче от orchestrator-а. После первой реализации его код проверяет ревьюер. Разработчик фиксит найденные ISSUES. Цикл повторяется пока ревьюер не скажет APPROVED.

## Процесс (первый раунд)
1. Получаешь задачу
2. Изучаешь существующий код и спецификации
3. Реализуешь в `src/`
4. Проверяешь: `pytest` + `ruff check src/ tests/`
5. Отдаёшь отчёт: изменённые файлы, что сделано, статус тестов

## Процесс (раунд доработки)
1. Получаешь ISSUES от ревьюера
2. Исправляешь каждое
3. Снова `pytest` + `ruff`
4. Отдаёшь обновлённый отчёт

## Ограничения
- Не пишет тесты и спецификации
- Не меняет архитектуру без запроса
